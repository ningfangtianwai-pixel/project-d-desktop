## 执行顺序

1. 权利人先选择源码许可证，并确认是否接受外部贡献。
2. 清理或补齐全部分发素材授权；未通过的资源从公开包中排除。
3. 确定运营主体和联系渠道，完成隐私政策、用户协议与安全响应流程。
4. 配置签名和正式更新基础设施，验证安装、升级、中断和回滚。
5. 完成真实硬件矩阵与 24 小时浸泡，关闭 P0/P1 问题。
6. 生成最终 SBOM、安装包哈希、签名信息、测试报告和发布说明。

## 许可证选择说明

当前不建议由开发工具自动替用户选择许可证。MIT/Apache-2.0/GPL 等方案对再分发、专利、衍生作品和商业组合有不同影响，必须由权利人结合商业计划确认。确定前不添加占位 `LICENSE`，也不把其他仓库的许可证原样复制进来。

## Git 历史与隐私

本阶段只脱敏当前文件，不改写 Git 历史。历史 Commit 中的作者邮箱、旧绝对路径或已删除内容仍可能被访问。是否改写公开历史会影响 Commit ID、标签、分支和协作者克隆，必须由仓库所有者单独授权，并在改写前保存镜像备份、通知协作者、轮换任何曾暴露的秘密。

## 本轮范围外的脱敏项

全仓库复查仍在 `PROJECT_STATUS.md` 的历史运行记录中发现 3 条包含本机用户名的 `%APPDATA%` 实际路径。该文件不在本轮允许写入范围内，因此没有修改。公开发布前应在独立提交中将其替换为 `%APPDATA%\Project D\...`，并重新执行全仓库敏感路径扫描。
