# Project D V5.0 实施与验收计划

版本：V5.0 Draft 1  
日期：2026-07-24  
对应需求：`docs/ProjectD_V5.0_产品需求文档.md`

## 1. 计划目标

本计划把V5分成“代码可完成”“需要素材”“需要真实硬件”“需要证书/法务/基础设施”四类，避免继续用代码提交掩盖外部门禁。

本轮建议以公开免费Beta为目标，不接入真实支付。支付、账号和权益骨架保留，但不出现在免费版主流程中。

1. 确认V5仅做免费Beta，继续暂停支付。

5. 决定是否购买 Authenticode 证书。
6. 安排 Windows 10/11、多GPU、多显示器测试设备或测试人员。
7. 批准隐私政策、用户协议、免责声明和素材授权结论。

## 2.4 不能由代码替代

- 素材商业授权。
- 代码签名证书和可信时间戳。
- 法律审核。
- 真实显卡、多显示器、DPI、睡眠唤醒证据。
- 真实4小时和24小时经过时间。
- 用户对审美、角色动作和交互手感的最终判断。

## 3. 优先级

## P0：发布阻断

- 白屏、无法关闭、桌面图标或任务栏无法恢复。
- 文件丢失、覆盖、错误移动或撤销失败。
- 安装、升级、卸载后桌面损坏。
- API Key、个人路径或诊断隐私泄露。
- 当前源码无法打包或安装包与源码不一致。

## P1：公开Beta前完成

- 持久化自定义壁纸库。
- Live Photo/H.264导入和失败降级。
- 真实多屏/DPI/睡眠唤醒。
- 所有公开桌宠的基础动作包。
- 4小时/24小时浸泡。
- 签名、素材授权、法律文本。
- 100+项目整理密度和文件夹预览性能。

## P2：体验增强

- 原生 Explorer 图标坐标模式。
- 壁纸编辑器位置、字体、贴纸和模板增强。
- 天气多层混合和更精细的光效。
- 视觉模型角色设定工作流。
- 场景与建议引擎的日历/会议焦点信号。

## P3：后续优化

- 国际化。
- 更完整无障碍。
- Live2D/Spine。
- 社区、云同步、账号和支付。

## 4. 执行阶段

## Phase 0：V5基线冻结

目标：把当前本地工作树变成可追溯起点。

任务：

1. 审查当前全部Diff，确认没有误删功能、测试和资源。
2. 运行秘密、绝对路径和私人文件名扫描。
3. 提交 Stage 50，建立 `v5-baseline` 快照或标签候选。
4. 将版本改为 `0.3.0-dev`，统一关于页、诊断、安装包和日志版本。
5. 从干净 checkout 重新安装、构建和打包。

验收：

- 工作树清晰，Commit SHA唯一。
- `pnpm lint`、`pnpm typecheck`、Node、组件、Electron E2E、构建全部通过。
- 新安装包由同一Commit生成。
- 构建不依赖本机 `.env`、缓存、绝对路径和未提交资源。

依赖：无。  
建议工期：1-2个开发日。

## Phase 1：P0安全回归

目标：冻结桌面安全边界。

任务：

1. 首次、重复、快捷方式、开机启动。
2. 白屏、渲染崩溃、主进程强杀、配置损坏。
3. 整理激活、安全归位、托盘退出、纯净桌面退出。
4. Explorer忙碌、Explorer重启、睡眠唤醒。
5. idle退出不得产生虚假恢复提示。
6. 所有异常后检查图标、任务栏、壁纸和残留进程。

验收：

- 11项现有E2E持续通过，并增加安装包路径复测。
- 任何失败都执行兜底恢复。
- `HideIcons=0`、任务栏可见、Explorer响应、残留进程为0。
- 无已知P0。

依赖：Phase 0。  
建议工期：2-3个开发日。

## Phase 2：桌面整理闭环

目标：解决“透明容器”和“原生桌面排列”的长期语义差异。

任务：

1. 保留透明容器为稳定默认模式。
2. 设计原生Explorer图标坐标实验模式。
3. 原生模式执行前保存所有图标坐标快照。
4. 排列失败、分辨率变化和退出时可回滚。
5. 100+项目下验证2/4/6/8栏、折叠、滚动、拖动和预览。
6. 补齐场景的每屏映射、钉选资源和门户状态恢复。
7. 人工验证门户选择、搜索打开/定位/复制、场景保存/恢复。

验收：

- 虚拟容器不移动文件。
- 原生模式不改变文件路径，只改变坐标。
- 失败回滚后坐标与快照一致。
- 100+项目、四档DPI无重叠和不可点击控件。
- ActionPlan执行与撤销不覆盖同名文件。

依赖：Phase 1。  
建议工期：4-7个开发日。

## Phase 3：壁纸与媒体2.0

目标：让壁纸库从内置清单升级为可管理媒体系统。

任务：

1. 建立用户壁纸目录和元数据表。
2. 导入时计算哈希、去重、生成缩略图和静态封面。
3. 支持删除、收藏、容量限制和损坏索引重建。
4. 将壁纸DIY导出直接保存到用户库。
5. 支持H.264 MP4和Live Photo配对导入。
6. 解码失败自动切静态封面。
7. 每屏保存壁纸、裁剪、质量和暂停状态。
8. 原系统壁纸快照、恢复和软件退出策略明确。

验收：

- 静态图片100次设置无黑屏。
- 视频100次循环、300次切换无不可恢复失败。
- 损坏图片/视频不替换当前可用壁纸。
- 重启、Explorer重启、睡眠唤醒后恢复。
- 双屏独立壁纸与热插拔通过。
- 用户库损坏可重建，缓存不无限增长。

依赖：Phase 1；真实多屏在Phase 7。  
建议工期：5-8个开发日。

## Phase 4：天气视觉与性能

目标：提升真实感，同时保证轻薄本预算。

任务：

1. 将雨、雨光、雾、落叶、星光和光晕拆成可组合层。
2. 每层提供开关和强度，不默认全部开启。
3. 建立静态、节能、均衡、高质量四档。
4. 接入全屏、锁屏、睡眠、电池和低电量暂停策略。
5. 统计帧率、CPU、GPU、内存和降级原因。

验收：

- 静态壁纸待机CPU中位数不高于1%，P95不高于3%。
- 1080p动态壁纸CPU中位数尽量低于5%。
- 全屏出现后2秒内停止视频解码和高频特效。
- 24小时内存无单调增长。
- 核显机器无持续卡顿和桌面输入延迟。

依赖：Phase 3。  
建议工期：3-5个开发日。

## Phase 5：桌宠完整化

目标：让五个角色都达到可发布的最低动作标准。

代码任务：

1. 定义角色包清单、动作槽、帧率、锚点、碰撞框和服装槽。
2. 支持导入、预览、完整性检查和损坏降级。
3. 本地抠图工具增加裁剪和动作槽绑定。
4. 人格、话频率、动作频率和气泡全部实时读取设置。
5. 多屏、负坐标和窗口边缘行为复测。

素材任务：

- 四个非Luna角色分别提供 idle、walk、happy、thinking、sleep、interaction。
- 换装必须提供真实透明帧或骨骼资源。
- 每项素材补齐来源、作者和授权证据。

验收：

- 五角色切换无裁切、黑边和错误锚点。
- 每个角色六类动作可见。
- 人格测试句、主动气泡和AI回复一致。
- 角色可在整个虚拟桌面移动且不永久丢失。
- 无真实服装素材时不显示伪换装。

依赖：项目负责人提供素材。  
代码建议工期：4-6个开发日。  
素材工期：外部依赖。

## Phase 6：AI视觉工作流

目标：提供安全、可审核的角色设定辅助，而不是自动替用户做决定。

任务：

1. 定义视觉请求同意页和图片发送边界。
2. 定义结构化输出：类型、外观、人格候选、口吻、禁用词、动作建议、提示词。
3. 支持DeepSeek/MiMo/OpenAI-compatible中的已确认视觉模型。
4. 显示模型、预计费用、超时、重试和失败原因。
5. 输出先预览，用户确认后写入角色配置。
6. 对生成文本执行长度、字段、敏感内容和动作权限校验。

验收：

- 未同意时不上传图片。
- API Key不进入renderer、日志和诊断。
- 非法JSON、超时、限流和余额不足可恢复。
- 输出不能直接执行文件或系统动作。
- 人像、动物和物体各有成功/失败样本。

依赖：用户提供可用视觉模型Key和服务条款。  
建议工期：4-6个开发日。

## Phase 7：真实硬件与长期稳定性

目标：用证据替代理论兼容。

硬件矩阵：

| 维度 | 最低覆盖 |
|---|---|
| Windows | Win10 22H2、Win11 |
| GPU | Intel、AMD、NVIDIA |
| 屏幕 | 单屏、双屏、三屏一次 |
| 分辨率 | 1080p、2K、4K |
| 方向 | 横屏、竖屏、负坐标 |
| DPI | 100%、125%、150%、200% |
| 刷新率 | 60/120/144Hz混合至少一次 |

循环：

- 睡眠/唤醒20次。
- 锁屏/解锁20次。
- 显示器热插拔50次。
- Explorer重启20次。
- 壁纸切换300次。
- 视频循环100次。
- 4小时交互、24小时空闲。

证据：

- 设备信息、构建SHA、操作步骤、截图、录屏、日志、CSV/JSON性能报告。
- 每个失败对应问题编号、严重级别、复现率和结论。

依赖：真实设备和经过时间。  
建议日历时间：至少3-5天。

## Phase 8：安装、签名、法律与素材

目标：关闭公开分发门禁。

任务：

1. 全新安装、覆盖安装、中文路径、标准账号、无网和卸载。
2. 验证保留数据/彻底删除两条卸载路径。
3. 验证N-1到N；自动更新未启用时保留手动GitHub Releases。
4. 生成SHA256、SBOM、Commit SHA和构建摘要。
5. 对安装包、卸载器和更新包签名并加时间戳。
6. 确认MIT代码权属和第三方依赖兼容性。
7. 33项现有素材及新增素材逐项批准或从公开包移除。
8. 定稿隐私政策、用户协议、免责声明和支持入口。
9. 启用GitHub私密漏洞报告或安全邮箱。

验收：

- `verify:release-ready`所有阻断项关闭。
- 安装包签名状态Valid。
- 公开包内不存在 `pending-evidence` 素材。
- 法律文本与实际数据行为一致。
- 安装、卸载后系统桌面正常且无残留进程。

依赖：证书、权利人、素材证据、法律审核。  
建议日历时间：3-10天，取决于外部输入。

## Phase 9：RC与公开Beta

目标：小范围真实用户验证。

步骤：

1. RC0：项目负责人本机和第二台机器。
2. RC1：10-30名明确告知风险的测试者。
3. RC2：50-100名免费Beta测试者。
4. 每一轮只扩大已通过硬件和素材范围。

退出条件：

- P0为0。
- P1有明确处置，不涉及桌面、文件、安装和秘密安全。
- 崩溃、恢复、安装和性能报告与对应版本关联。
- 支持入口、已知问题、回滚包和用户通知模板准备完成。

## 6. 风险登记

| 风险 | 严重度 | 对策 |
|---|---|---|
| WorkerW/Progman在系统更新后变化 | P0/P1 | 多路径探测、健康检查、静态降级、恢复脚本 |
| 原生图标坐标API不稳定 | P1 | 实验开关、完整快照、失败回滚、默认仍用透明容器 |
| 视频解码黑屏或高占用 | P1 | H.264基线、封面降级、暂停仲裁、性能档位 |
| 非Luna素材不足 | P1 | 不伪造动作；素材未齐不进入公开角色列表 |
| API服务变更或余额不足 | P2 | 本地降级、连接测试、错误分类、BYOK |
| 未授权素材进入安装包 | P0 | `distributionEnabled=false`默认拒绝构建 |
| 未签名导致SmartScreen阻断 | P1/发布阻断 | Authenticode和时间戳 |
| 长浸泡内存增长 | P1 | 缓存配额、资源所有权、4/24小时趋势报告 |
| V5范围继续扩张 | P1 | 功能冻结后新增需求进入V5.1/V6 |

## 7. 推荐执行顺序

1. Phase 0：先形成可靠基线。
2. Phase 1：锁死P0恢复路径。
3. Phase 3：完成用户壁纸库和媒体管线。
4. Phase 2：整理规模和原生布局实验。
5. Phase 4：天气与性能。
6. Phase 5：桌宠代码；素材工作可并行。
7. Phase 6：视觉AI，必须晚于隐私边界确认。
8. Phase 7：硬件与长浸泡。
9. Phase 8：签名、法务、授权和安装。
10. Phase 9：RC与公开Beta。

Phase 2、3、5可由不同开发任务并行，但不能同时修改同一主进程生命周期或设置模型。Phase 7与8的外部准备应从第一天开始，不能等代码结束才寻找设备、证书和授权。
