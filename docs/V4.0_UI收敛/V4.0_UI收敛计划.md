# Project D V4.0 UI 收敛工作计划

> 日期：2026-07-24  
> 基线：Stage 51 / 26170 行 / 235 测试 / 768 ACC  
> 目标：把控制台式界面收敛为沉浸式桌面层体验

---

## 一、现状问题

当前 Project D 打开后的默认界面是一个**功能控制台**：

- 虚拟分区容器铺满屏幕中央
- 搜索框、收件箱、刷新、归位按钮挤在顶栏
- 桌宠气泡、建议卡片、ChatPanel 三个独立入口
- 容器毛玻璃面板覆盖主要视觉空间
- 壁纸沦为背景而非主角

**问题本质：不是功能不够，是功能全部同时显示。**

---

## 二、V4.0 收敛目标

> 用户打开 Project D，第一眼看到的是一张完整、安静、有呼吸感的桌面，而不是一个文件管理器。

**核心指标：**
- 默认态面板覆盖面积 ≤ 20%
- 一级入口 ≤ 5 个
- Luna 是唯一助手入口
- 同时展开面板 ≤ 1 个
- 安全归位始终可达

## 四、分阶段工作计划

### Phase A：安静默认态（3-5 天）

**目标：** 用户打开时只看到壁纸 + 左侧快捷轨 + 右侧 Luna

**改动清单：**

1. **OverlayPage 重写**（`renderer/views/OverlayPage.vue`）
   - 移除默认全铺文件网格
   - 默认只显示一个克制的状态摘要条（底部小浮层）
   - 文件网格仅在用户点击"桌面内容"快捷轨时才展开
   - 容器变为按需面板而非常驻区域

2. **快捷轨完善**（`renderer/App.vue` + `renderer/styles.css`）
   - 4 个入口：搜索 / 桌面内容 / 收件箱 / 场景
   - 每个入口：图标 + 点击展开面板
   - 悬停时显示标签文字
   - 安全归位按钮固定在右下角，视觉克制
   - 键盘 Tab 导航 + 焦点环

3. **安静态状态机**（`renderer/App.vue`）
   - `data-active-task-surface="none"` 时：壁纸完整可见，Luna 低频待机
   - `data-active-task-surface="search"` 时：搜索面板从左侧展开
   - 其他任务面板互斥展开

**验收标准：**
- 1920×1080 默认截图中，面板覆盖面积 ≤ 20%
- 一级入口 = 4 个快捷轨 + 1 个安全归位 = 5 个 ✅
- Win+D、任务栏、开始菜单不被破坏
- 退出后 Windows 桌面恢复正常

### Phase B：Luna 助手统一（2-3 天）

**目标：** Luna 成为右侧唯一助手入口

**改动清单：**

1. **Luna 助手面板组件**（`renderer/components/LunaAssistant.vue`，新建）
   - 单击 Luna：展开/收起助手面板
   - 助手面板包含：状态气泡 + 建议列表 + 对话入口
   - 气泡最多两行，超出进入面板

2. **合并现有入口**
   - ChatPanel 的对话功能 → Luna 面板内
   - 建议卡片 → Luna 面板内
   - 桌宠气泡 → 保留但归入 Luna 系统

3. **Luna 位置策略**
   - 固定右侧安全区（右下角任务栏上方）
   - 多显示器时只在主屏显示
   - 全屏应用时自动隐藏

**验收标准：**
- 用户可从 Luna 完成"查看建议 → 打开方案 → 确认或取消"
- 同一建议不在多处重复出现
- 无内容时右侧只保留角色和最小状态

### Phase C：单任务面板（2-3 天）

**目标：** 任意时刻最多一个工作面板展开

**改动清单：**

1. **统一工作面板容器**（`renderer/components/TaskPanel.vue`，新建）
   - 统一的展开/收起动画（160-240ms）
   - Escape 关闭
   - 点击空白关闭（无未保存内容时）
   - 焦点管理

2. **四类面板适配**
   - 搜索面板：输入 + 结果 + 动作
   - 整理面板：摘要 + 方案 + 确认
   - 场景面板：列表 + 保存 + 恢复
   - 桌面内容面板：分区网格 + 文件预览

3. **互斥状态机**
   - 展开 A 时自动收起 B
   - 切换不丢失未提交输入（草稿保留）
   - 高风险操作不能因自动收起绕过确认

**验收标准：**
- 任意时刻最多 1 个主工作面板展开
- Escape 关闭当前面板
- 完成任务后一次动作返回安静态

### Phase D：视觉统一（3-5 天）

**目标：** 所有组件使用统一的玻璃材质和动效令牌

**改动清单：**

1. **CSS 令牌系统**（`renderer/styles/tokens.css`，新建）
   - `--glass-bg`、`--glass-border`、`--glass-blur`、`--glass-shadow`
   - `--radius-sm`、`--radius-md`、`--radius-lg`
   - `--transition-panel`（160-240ms）
   - `--space-xs`、`--space-sm`、`--space-md`
   - 暗色/亮色壁纸自适应色值

2. **全局样式统一**（`renderer/styles.css` 重构）
   - 将 40 处 glassmorphism 引用替换为令牌引用
   - 确保亮色/暗色壁纸下文字可读
   - DPI 适配（100%/125%/150%/200%）

3. **动效统一**
   - 面板展开/收起：`var(--transition-panel)`
   - Luna 待机动作：低频、可暂停
   - 全屏/电池/锁屏暂停所有非必要动画

**验收标准：**
- 6 张明暗/复杂度不同的壁纸上，文本和图标清晰可读
- 100%-200% DPI 无裁剪、重叠
- 减少动态效果后无持续位移动画

## 七、注意事项

1. **不改底层能力** — Phase A-D 只改展示层，不改搜索引擎、ActionEngine、数据库等
2. **不丢功能** — 所有现有功能通过快捷轨或二级面板可达
3. **安全归位不可藏深** — 始终在一级可达位置
4. **旧用户过渡** — Phase D 完成后提供短期"经典布局"切换，不长期维护两套
5. **每次 Phase 完成后截图对比** — 用当前状态图 vs 新截图，量化面板覆盖面积变化
