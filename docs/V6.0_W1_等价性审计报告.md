## 1. 架构事实（必须先用对心智模型）

Project D 不是"单窗口 + 多路由"，而是 **1 个主壳窗口 + 多个独立 BrowserWindow**，每个窗口承载一个 `#/` 路由：

- `mainWindow`（`""`）→ `App.vue` 沉浸壳：WallpaperStage + EdgeRail + AmbientStatus + AmbientFileSpace + OrganizerSurface / SearchSurface / SceneSurface / AssistantSurface + CompatibilitySurface。
- `overlayWindow`（`#/overlay`）→ `OverlayPage.vue`（旧整理控制台）。
- `petWindow`（`#/pet`）→ `PetPage.vue`（桌宠本体，`setAlwaysOnTop("screen-saver")`，透明可交互）。
- `wallpaperWindow`（`#/wallpaper`）→ 真正的壁纸渲染窗（含 `WallpaperStage`，开机若开启动态壁纸自动创建）。
- `settingsWindow`（`#/settings`）→ `SettingsPage.vue`。

`App.vue` 仅当 `window.location.hash` 为 `#/overlay|#/pet|#/wallpaper|#/settings` 时，才把主壳整窗切换到对应旧视图；否则永远渲染新沉浸壳。

**关键纠偏**：原计划（及我 7-30 的收尾计划）假设"默认界面已唯一是新壳、旧页面只是次级入口"。实际不成立——见 §3。

## 2. 逐页面能力映射

### 2.1 PetPage（#/pet）— 桌宠本体窗口
- 证据：`src/main/main.ts:374` `"#/pet": petWindow`；`:1045` `createPetWindow()` → `loadRendererWindow(window, "#/pet", "pet")`；`:1090` 加载；`pet-ipc.ts` 用 `assertTrustedSender(["#/pet"])` 限定。
- 新 Surface（`AssistantSurface` / `SceneSurface` / `AmbientStatus`）只**读取** `petVisible` / `petAnchor` 渲染**静态头像/缩略图**，不承载实时桌宠。
- **等价结论**：删 `PetPage` = 删掉活的桌宠。❌ 不可删。重分类为"companion window"，与 wallpaperWindow 同级。

### 2.2 WallpaperPage（#/wallpaper）— 壁纸管理工作台
- 能力：内置+个人壁纸库、导入图片、导入 Live Photo（真实解码校验）、应用、删除个人壁纸、导出原图、每屏分配、每屏 fit 模式、视频预览播放/暂停。
- 新 Surface：`SceneSurface` 仅做"换一张 + 打开壁纸库"按钮，点"壁纸库"即 `openWallpaperPage()` 把主壳切到 `WallpaperPage`。`wallpaperWindow` 只渲染壁纸，无管理能力。
- **等价结论**：没有任何新 Surface 复刻"导入/Live Photo/分屏分配/导出"。❌ 不可删。`WallpaperPage` 是正确保留的按需工作台（与设置页同级）。

### 2.3 OverlayPage（#/overlay）— 旧整理控制台
- 能力全集：容器拖拽移动、容器缩放/折叠、容器配色、文件夹门户（增删/列资源）、桌面收件箱方案（生成/执行/撤销）、工作区搜索（打开/定位/复制路径/钉场景/授权门户）、场景保存/应用、壁纸切换、文件富预览（文本/图片/文件夹）、右键菜单、布局切换、建议 toast。
- 新 Surface 覆盖情况：
  - `OrganizerSurface`（activeSurface='organize'）：✅ 容器与文件**展示**、点击选中、双击打开、右键菜单（经 `App.vue` 共享菜单）、收件箱方案、扫描、安全归位、纯净桌面。❌ **无拖拽移动/缩放容器、无配色、无文件夹门户、无富文件预览**（仅显示选中文件名+路径）。
  - `SearchSurface`：✅ 覆盖工作区搜索（打开/定位/复制/钉场景/授权门户）。
  - `SceneSurface`：✅ 覆盖场景保存/应用、壁纸切换。
- **等价结论**：OrganizerSurface 是 OverlayPage 的"瘦身版"，**缺少拖拽布局 / 门户 / 富预览**三类能力。`OverlayPage` 目前**不可替代**。

## 3. 最关键的发现：旧 Overlay 仍是"激活桌面"的主界面

`main.ts` 中 `createOverlayWindow()` 被三处调用：

- `:1657` `scheduleDemoAutorun` —— 仅 `PROJECTD_DEMO_AUTORUN=1` 时（QA/演示），非日常。
- `:2037` `startTray` → 托盘菜单"激活桌面"：`createOverlayWindow(...)` 后 `mainWindow?.hide()`。
- `:2882` 开机自启偏好为"激活桌面"时：`createOverlayWindow(false)` 后 `mainWindow?.hide()`。

**含义**：
- 当用户从**托盘菜单**或**开机自启**激活桌面时，应用弹出**旧 `OverlayPage` 独立窗口**作为主 organizer，并**隐藏新沉浸壳**。
- 只有从**新壳内部的"激活/整理"按钮**进入（`App.vue` 的 `activateDesktop` → `openDesktopSurface('organize')`）才走新 OrganizerSurface。
- 因此"新沉浸壳是默认体验"在托盘/开机路径下**不成立**。删除 `OverlayPage` 会直接让这两条激活路径失活。

这解释了为何代码里新旧 organizer 并存——**迁移尚未完成**，激活接线仍指向旧 overlay。

## 4. 修正后的 Phase H 范围（取代原"删旧控制台"）

原计划的删除清单需改为：

| 项 | 新处置 |
|---|---|
| 删 `PetPage` | ❌ 取消。保留为 companion window。 |
| 删 `WallpaperPage` | ❌ 取消。保留为按需工作台。 |
| 删 `OverlayPage` | ⚠️ 暂缓。需先完成 §5 的接线改造 + 能力补齐，否则破坏激活路径。 |
| 清理重复 CSS / 状态 | ✅ 保留。在 §5 改造后做。 |

**正确的收尾顺序（W2 起）：**
1. **接线改造（先，低风险）**：把托盘/开机"激活桌面"从 `createOverlayWindow()+hide(main)` 改为"显示主壳 + 打开 OrganizerSurface"。让新沉浸壳成为唯一激活入口。
2. **能力补齐（中风险，需决策）**：在 `OrganizerSurface` 复刻缺失的三类能力（拖拽布局 / 门户 / 富预览），或**产品上决议放弃**这些能力（若新设计有意用"自动布局+收件箱方案"取代手动拖拽）。
3. **停止创建 overlayWindow**：移除 `createOverlayWindow` 调用 + `OverlayPage.vue` + 相关 IPC 信任名单里的 `#/overlay`。
4. **CSS / 状态清理**：删重复样式与 `#/overlay` 路由分支。
