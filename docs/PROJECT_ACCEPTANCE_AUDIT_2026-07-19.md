# Project D 项目验收复核报告

评估对象：Project D `0.2.0-beta.1` 及 2026-07-19 工作区代码

评估依据：V1.1 验收标准、V2.1/V3.0 商业化方案、Stage 41 内测基线、外部《Project D 综合评估报告》

结论日期：2026-07-19

## 1. 最终判断

| 发布目标 | 结论 | 判断依据 |
|---|---|---|
| 当前电脑上的开发与功能测试 | **通过** | 完整质量门禁、强杀恢复和当前代码的打包态烟测均通过 |
| 小范围、明确告知风险的内部 Beta | **有条件通过** | 当前受测范围内无已知 P0；必须注明未签名、仅 Windows 当前设备实测、素材仍待商业授权 |
| 面向公众的免费 Beta | **暂不放行** | 缺 Authenticode、干净 Win10/11 与真实硬件矩阵、长时间稳定性及完整素材授权证据 |
| 收费商业版 / GA | **不通过** | 生产账号支付后端、真实更新与运维基础设施、法律文本和商业资质均未完成 |

**P0 判断：** 在自动化覆盖到的启动、数据库、桌面恢复、壁纸恢复、渲染器自愈、退出与打包运行范围内，没有发现仍未修复的 P0。这个结论不外推到尚未执行的 Win10、多显卡、多屏、高 DPI、睡眠唤醒和 24 小时物理测试。

用两个维度看进度更准确：客户端功能与受控内测准备度约 **85% 到 90%**；严格商业 GA 准备度约 **40% 到 45%**。外部报告给出的 35% 忽略了已存在的安全配置、CI、SBOM、远程配置和本地运维能力，但其对签名、生产后端、法律与硬件证据的否决结论是正确的。

## 2. 本轮直接修复

1. **密钥存储改为严格失败关闭。** Electron `safeStorage` 不可用时不再写入或读取兼容明文 API Key，并清除迁移时发现的旧明文值；用户必须在系统凭据加密恢复后重新配置。
2. **Provider 配置脚本不再直接写数据库秘密值。** `pnpm configure:providers` 现在由 Electron 启动，并复用正式 `DatabaseService` 与 `safeStorage` 路径；应用运行中或加密不可用时拒绝操作。
3. **日志系统补全。** 支持 `DEBUG/INFO/WARN/ERROR`、JSON 结构化记录、级别过滤、序列化异常隔离、5 MiB 默认轮转与保留上限；写日志失败不会拖垮主进程。
4. **主进程继续拆分。** 托盘和全局快捷键分别迁入 `ProjectTrayManager` 与 `ShortcutManager`；快捷键冲突保留旧绑定，退出时统一释放资源。
5. **渲染器安全基线固化。** 五个 `BrowserWindow` 均显式启用 `sandbox`、`contextIsolation`、`webSecurity`，禁用 `nodeIntegration`，并增加静态回归测试。
6. **移除显式 `any`。** 覆盖层图标表和文件预览返回值改为明确类型；当前 `src` 中未发现 TypeScript `any` 类型残留。
7. **建立覆盖率硬门禁。** 新增 `pnpm test:coverage`，CI 低于行 80%、分支 70%、函数 80% 会失败，并上传覆盖率证据。
8. **诊断读取器与新日志级别对齐。** `DEBUG` 记录可作为信息级诊断元数据读取，不再被当作未知格式丢弃。

## 3. 外部报告复核

### 已确认属实

- `src/main/main.ts` 仍有 2325 行，虽然本轮减少约 300 行，但窗口、壁纸宿主和生命周期编排仍应继续拆分。
- GUI E2E、Vue 组件测试和系统化可访问性测试仍不足。
- 生产服务端仍是领域骨架，没有真实 HTTP、持久化数据库、认证、支付渠道、对账和灾备。
- 安装包未签名；生产 HTTPS 更新源、服务端告警传输与商业运维后台未部署。
- 真实多屏/DPI/GPU/Win10/Win11/睡眠唤醒以及 4 小时、24 小时测试证据未完成。
- 33 项分发素材均处于 `pending-evidence`，不能据此宣称商业版权已完成。
- 安装体积、i18n、无障碍和统一错误模型仍有产品化空间。

### 已过时或本轮已关闭

| 报告结论 | 当前事实 |
|---|---|
| 无远程配置签名验证 | 已有 Ed25519 验签、环境绑定、过期校验、SHA-256、单调 revision cursor、防回滚与受保护核心能力 |
| 缺少 sandbox、CSP、webSecurity | 五个窗口均启用 sandbox/contextIsolation/webSecurity，关闭 Node integration；`index.html` 有 CSP，并有回归测试 |
| 无 CI/CD | 已有 GitHub Actions 质量门禁；自动生产发布仍未完成，因此属于“有 CI、无完整 CD” |
| 无 SBOM 和依赖审计 | CycloneDX SBOM 含 358 个组件，当前 npm 审计 0 个已知漏洞 |
| 无功能开关 / kill switch | 已有签名远程操作策略、资产与版本停用、受保护桌面核心以及本地持久化 cursor |
| 可观测性为零 | 已有本地结构化日志、运行指标、崩溃聚合、告警规则和恢复中心；缺的是生产上传与服务端看板 |
| 无日志级别、结构化和轮转 | 本轮已关闭 |
| `any` 残留 | 本轮已关闭 |
| 无覆盖率报告 | 本轮已关闭并成为 CI 硬门禁 |

“必须迁移 Vitest”不是验收结论。Node test runner 当前可稳定提供 175 项测试与原生覆盖率；是否迁移应由维护收益决定，不能为了工具名称产生大规模测试改写。类似地，当前类型化手工依赖组合并不天然低于 DI 容器；在依赖图出现真实维护痛点前，引入 `tsyringe` 或 `inversify` 不是商业化阻断项。

## 5. 后续仍可直接由代码推进

1. 将窗口创建/恢复、WallpaperHost 编排和应用生命周期继续从 `main.ts` 拆出，并给边界增加集成测试。
2. 建立 Playwright Electron 的少量 P0 流程：首次启动、设置窗口、重复启动、壁纸失败恢复、干净桌面退出、托盘退出。
3. 增加 Vue 设置页关键组件测试和统一的可见错误边界。
4. 把启动耗时、搜索 P95、动态壁纸帧率、进程内存、句柄和日志增长变成带阈值的性能报告。
5. 继续审计事件监听器、Pixi 纹理释放和窗口销毁路径；用 4 小时/24 小时结果决定是否存在泄漏，而不是凭代码猜测。
6. 优化安装体积：统计资源贡献，评估壁纸按需包与图片编码；不能为了体积删除核心离线能力。
7. 在明确目标市场后补 i18n 与可访问性基线；这需要产品范围，但不依赖第三方资质。

## 7. 发布建议

当前版本可以继续用于本机开发和小范围受控内测，但内测说明必须明确“未签名、非商业发布、素材授权待审、硬件矩阵未完成”。不要把现有 EXE 直接宣传为商业稳定版，也不要接入真实付款。

下一次公开 Beta 放行至少应同时满足：签名有效、干净 Win10/11 安装升级卸载通过、最低真实硬件矩阵通过、4 小时与 24 小时报告通过、全部随包素材获得商业授权、生产更新域与回滚演练通过。收费 GA 还必须在其上完成服务端账号支付闭环、安全评审、灾备和法律审批。
